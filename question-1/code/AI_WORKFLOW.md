# AI 协作

从需求到现在这版商店，人负责判断，agent 负责按已写下来的约束改文档和代码。素材在 `AI_NOTES.md`。这里只留面试要讲的几件事。

## 谁做什么

人澄清需求、否定错误前提、决定不做加分题。agent 先读 `AGENTS.md`、`SPEC.md` 和方案，再改代码。价格、库存和订单不在页面里另算。

刻意不交给 agent 的部分：

- API key 不写进代码、`.env` 或笔记。对话栏每次由人填写。
- 不加分题里的福袋、开卖时间和并发抢购。
- 不把毛利率乘进推荐分，也不在响应里返回毛利率。

## Harness 怎么约束

约束放在仓库里，不依赖某一次对话还记不记得。

- `AGENTS.md` 规定实现顺序、价格只有一份、加购不下单、不建 MCP。
- `src/domain/pricing.js` 是唯一的价格实现。网页和接口都不能另写一套。
- 仓库根目录的 `.github/workflows/test.yml` 会在 `question-1/code` 里启动 `npm start`，再由 `scripts/verify-pricing.js` 核对报价。公式被改错时，推送过不了。GitHub 只读取仓库根目录的 workflow。
- `skills/shop-quote/SKILL.md` 约束对话栏怎么解释应付金额。服务启动时读进系统提示，模型不能另算价格。

选这一个 skill，是因为报价说明会原样进入对话。它如果写成「页内一律没有 95 折」，店员会否定页面上已经按 AI 下单算出的应付金额。价格公式本身仍只在 `pricing.js`。

它改过 3 版，每一次都在 git 历史里，没有并进别的提交：

## 失败和修正

### 1. 对话被写成另一个页面

`技术方案.md` 最初把 agent 做成独立页面。人指出对话是商城右侧的侧边栏。方案和页面都改成侧边栏，没有单独路由。见 `AI_NOTES.md` 第 1 则。早期页面在提交 `584757a`。

### 2. 付款后库存没有减少

结账写了订单，可售数量仍读商品文件里的库存。可售改为目录库存减去已售和未过期预留，`products.json` 不改。见 `AI_NOTES.md` 第 5 则，提交 `77b4c9d`。

### 3. 页内对话被当成 AI 订单

先做成对话栏直接下单才有 95 折，人在购物车结账没有。见 `AI_NOTES.md` 第 20 则和当时的 `DECISIONS.md` 第 10 条。

人更正：页内对话仍是人在操作。95 折只给外部 API，以及本机 `/?as=agent` 这个带标识的页面。页内普通访问改回人类价。见 `AI_NOTES.md` 第 24 则、第 25 则，以及 `DECISIONS_V2.md` 第 0 条、第 12 条。

### 4. 商品变多时的推荐来回改了一次

先反对一次返回全部商品。随后做成 1000 件以上由推荐算法排序。人再判断：1000 件以上仍先检索，把命中的一页交给模型，不让算法成为最终排序。见 `AI_NOTES.md` 第 21 到 24 则，`DECISIONS_V2.md` 第 11 条。提交 `cd908a4` 是算法那一版，当前代码已改回检索。

### 5. 只跑单元测试还不能说明服务算对了

Actions 最初只执行价格单测。人要求启动项目后再验证。工作流改为 `npm start` 之后请求 `/api/quotes`。见 `AI_NOTES.md` 第 30 则和 `scripts/verify-pricing.js`。
